# Технический план: скилл доступа к аккаунту Bybit

Статус: черновик на утверждение
Версия: 0.1
Дата: 2026-09-25
Основан на: `spec.md` версии 0.2

Документ описывает КАК реализуется спецификация.

## 1. Суть решения

CLI на TypeScript, собираемый в один самодостаточный файл, плюс `SKILL.md` с
инструкциями для агента. Агент вызывает команды CLI и интерпретирует их вывод.
Пользователь CLI руками не запускает.

Повторяется схема, проверенная на t-invest: агент не ходит в API напрямую, между
ним и биржей стоит слой, который отвечает за подпись запросов, пагинацию,
единицы измерения и честность расчётов.

## 2. Стек и ограничения

- TypeScript, Node.js 20 и новее, модули ESM.
- Рантайм-зависимости: `commander` (разбор аргументов) и `dotenv` (чтение
  ключа). Больше ничего. Подпись запросов делается штатным `node:crypto`.
- Сборка: `esbuild` в один CommonJS-файл. У пользователя нет ни установки
  пакетов, ни сборки — только Node.
- Тесты: `vitest`, рядом с каждым модулем.

Отказ от готового SDK `bybit-api` сознателен: он хорош, но тянет зависимости и
ломает главное свойство установки — «нужен только Node». Подпись занимает
десяток строк, ради них зависимость не нужна.

## 4. Слои

**Транспорт (`api/`).** Один модуль умеет выполнять подписанный и неподписанный
запрос, разбирать конверт ответа Bybit (`retCode`, `retMsg`, `result`) и
превращать отказ в типизированную ошибку.

**Команды (`commands/`).** Каждая команда — чистая функция: принимает клиент API
и параметры, возвращает структуру данных. Не печатает и не читает аргументы.

**Регистрация (`cli/`).** Разбор аргументов, вызов команды, выбор формата
вывода. Отделено от логики, чтобы команды тестировались без CLI.

**Форматирование (`format/`).** Таблицы для человека, JSON для агента.

## 5. Карта эндпоинтов

Все пути ниже сверены с исходниками pybit.

**Доступ (FR-1)**
- `GET /v5/user/query-api` — права ключа, срок действия, тип. Основа проверки
  «только чтение».
- `GET /v5/account/info` — режим счёта, единый он или нет.
- `GET /v5/market/time` — время биржи, для диагностики рассинхрона часов.

**Счёт и активы (FR-2, FR-3, FR-4)**
- `GET /v5/account/wallet-balance` — единый торговый счёт: эквити, маржа,
  остатки по монетам.
- `GET /v5/asset/transfer/query-account-coins-balance` — остатки по кошельку
  финансирования.
- `GET /v5/position/list` — открытые позиции по бессрочным и опционам.
  `category` только `linear`, `inverse`, `option`; `settleCoin` одно значение,
  поэтому `linear` запрашивается отдельно по USDT и USDC.
- `GET /v5/account/option-asset-info` — нереализованный и реализованный
  результат, маржа и дельта по опционам в разрезе базовой монеты.
  `totalPerpUPL` из `wallet-balance` опционы не включает.
- `GET /v5/asset/asset-overview` — итог в долларах по каждому счёту (торговый,
  финансирования, Earn). Используется итог кошелька финансирования: сам
  `query-account-coins-balance` отдаёт только количества.
  Для Earn используются итог и `coinDetail` оттуда же (A-2): отдельных запросов к
  продуктам Earn нет.

**Опционы (FR-5, FR-6)**
- `GET /v5/asset/coin-greeks` — нетто-греки портфеля в разрезе базовой монеты.
  Гамма, вега, тета отсюда; дельта здесь включает спот и бессрочные, поэтому
  дельта берётся из `option-asset-info` (только опционы).
- `GET /v5/asset/portfolio-margin` — разбор маржи Portfolio Margin: итог счёта,
  маржа по базовой монете, сетка сценариев цены и IV, убыток по позициям.
- `GET /v5/market/tickers` с `category=option` и `baseCoin` — вся доска по
  монете одним запросом: цены, IV покупки, продажи и маркировки, греки, объём,
  открытый интерес.
- `GET /v5/market/instruments-info` с `category=option` — параметры контрактов:
  дата и время экспирации (`deliveryTime`), тип, шаги цены и количества. Страйка
  отдельным полем нет — он разбирается из символа. Постранично (до 1000), без
  `baseCoin` отдаёт только BTC, `baseCoin=All` — все монеты.
- `GET /v5/market/delivery-price` — цены расчёта прошедших экспираций.
- `GET /v5/market/historical-volatility` — историческая волатильность.

**История (FR-7, FR-8, FR-9)**
- `GET /v5/execution/list` — исполнения. Окно запроса 7 дней, глубина 2 года.
- `GET /v5/account/transaction-log` — журнал операций. Окно 7 дней, глубина
  2 года.
- `GET /v5/position/closed-pnl` — закрытые позиции по бессрочным. Окно 7 дней,
  глубина 2 года.
- `GET /v5/position/get-closed-positions` — закрытые опционные позиции.
- `GET /v5/asset/delivery-record` — исполнения на экспирации. Глубина 2 года.

**Движение средств (FR-13)**
- `GET /v5/asset/deposit/query-record` — вводы из блокчейна. Окно 30 дней.
- `GET /v5/asset/deposit/query-internal-record` — вводы внутри Bybit.
- `GET /v5/asset/withdraw/query-record` — выводы, включая внутренние.
- `GET /v5/asset/transfer/query-inter-transfer-list` — переводы между своими
  кошельками. Запрашивается только для того, чтобы исключить их из расчёта.

**Рынок и справочник (FR-10, FR-11)**
- `GET /v5/market/tickers`, `GET /v5/market/kline`, `GET /v5/market/orderbook`,
  `GET /v5/market/recent-trade`, `GET /v5/market/instruments-info`.

## 6. Ключевые решения

**D-1. Транспорт умеет только GET.** В HTTP-слое не реализован метод POST — ни
одной функции, которая может его отправить. Требование NFR-1 становится
структурным свойством кода, а не дисциплиной разработчика. Тест проверяет, что
в собранном бандле нет ни изменяющих путей, ни отправки тела запроса. Это же
решение закрывает критерий приёмки 20.

**D-2. Подпись.** Заголовки `X-BAPI-API-KEY`, `X-BAPI-TIMESTAMP`, `X-BAPI-SIGN`,
`X-BAPI-RECV-WINDOW`. Подписывается строка `timestamp + apiKey + recvWindow +
queryString`, HMAC-SHA256, результат в нижнем регистре шестнадцатеричным.
Поскольку запросы только GET, вариант с телом не нужен.

**D-3. Часы.** Биржа отвергает запрос, если локальное время ушло. Перед первым
подписанным запросом сессии сверяем время с `/v5/market/time` и при
расхождении больше секунды сообщаем об этом прямо, называя разницу. Это самая
частая причина отказов, и она обязана диагностироваться, а не выглядеть как
«неверный ключ».

**D-4. Числа.** Bybit отдаёт все величины строками. Строки сохраняются как есть
для отображения, арифметика делается в числах с плавающей точкой. Для сумм в
долларах и количеств криптовалют точности достаточно с огромным запасом.
Округление при выводе — по шагу цены и количества конкретного инструмента из
справочника, а не по фиксированному числу знаков.

**D-5. Оконная пагинация — один общий механизм.** Исторические эндпоинты
ограничивают длину одного запроса (7 дней у торговых, 30 у движения средств) и
отдают страницы по курсору. Один хелпер режет запрошенный период на окна,
внутри окна идёт по курсору и склеивает результат. Все исторические команды
пользуются им, каждая передаёт лишь размер своего окна. Он же отвечает за
соблюдение лимита запросов и за сообщение о прогрессе при длинной выборке.

**D-6. Доска опционов собирается двумя запросами.** Рыночная часть — один вызов
`tickers` с `category=option` и базовой монетой, который возвращает сразу все
контракты по ней с греками и IV. Параметры контрактов (страйк, экспирация, тип)
берутся из `instruments-info` и кэшируются. Дальше всё — локальная фильтрация и
сортировка. Дорогих циклов по контрактам нет.

**D-7. Кэш справочника.** Файловый кэш инструментов, как в t-invest. Срок
жизни для спота и бессрочных — сутки, для опционов — часы: контракты
экспирируются, устаревший список вреден. Кэш лежит в каталоге конфигурации
пользователя, не в репозитории.

**D-8. Оценка в долларах (FR-13).** Стейблкоины считаются равными доллару, и это
помечается как точная оценка. Для остальных монет берётся дневная свеча пары
«монета/USDT» на дату операции, цена закрытия — помечается как расчётная с
указанием источника и даты. Если торговой пары нет или свеча недоступна,
значение возвращается пустым с причиной, и такая операция отдельно выделяется в
итоге. Приближений и подстановок нет.

**D-9. Сырые и расчётные данные разделены в выводе.** В JSON расчётные поля
собраны в отдельный объект `computed`, рядом с ними — `computedNotes` с
пояснением метода. В человекочитаемом выводе расчётные значения помечены.
Файл `references/` описывает по каждой команде, что именно вычисляется и в
каких случаях значение бывает пустым.

**D-10. Хранение ключа.** Ключ и секрет читаются из файла в каталоге
конфигурации пользователя, за пределами репозитория. В вывод, логи и сообщения
об ошибках они не попадают никогда.

## 8. Ошибки

Коды отказов Bybit переводятся в причину и действие:

| Ситуация | Что говорит скилл |
|---|---|
| Неверный или отозванный ключ | ключ не принят, проверить и пересоздать |
| Нет прав на запрошенные данные | у ключа нет права на запрос к эндпоинту (какому — называется; какое право нужно, биржа не сообщает), права ключа — в `session status` |
| Расхождение часов | локальное время ушло на N секунд, синхронизировать |
| Блокировка по географии | биржа не обслуживает запросы с этого адреса |
| Превышен лимит запросов | лимит исчерпан, когда освободится |
| Сервис недоступен | временный отказ биржи, повторить |

Отдельно: попытка запросить данные глубже, чем отдаёт биржа, не ошибка —
скилл возвращает данные и называет фактическую границу.

## 9. Тестирование

Юнит-тесты на фикстурах реальных ответов API, без сети:

- подпись запроса — сверка с эталоном;
- оконная пагинация — склейка без потерь и дублей на границах окон;
- разбор опционного контракта и сборка доски;
- оценка операций в долларах, включая случай отсутствия пары;
- расчёт нетто-ввода с исключением внутренних переводов;
- форматирование чисел по шагу инструмента;
- перевод кодов отказа в сообщения.

Отдельный тест-страж: в исходниках и в собранном бандле нет изменяющих путей и
нет отправки тела запроса.

## 10. Порядок реализации

Этапы независимы и каждый заканчивается работающим результатом.

**Э1. Каркас и доступ.** Транспорт, подпись, конфигурация ключа, ошибки,
`session status`. Готовность: скилл видит счёт и честно сообщает о проблемах.

**Э2. Счёт.** `portfolio`, `balance`, `positions`. Готовность: цифры сходятся с
интерфейсом биржи.

Учесть по живому прогону на счёте пользователя (2026-09-27):
- `GET /v5/position/list` отдаёт страницами (по умолчанию 20 позиций, дальше
  `nextPageCursor`): первый запрос вернул 20 из 26 опционных позиций. Позиции
  собираются проходом по курсору до конца, без потерь и дублей (NFR-7).
- Монета с ненулевым остатком, `marginCollateral=false` и `usdValue` равным 0:
  биржа такую монету не оценивает (документация WebSocket wallet). Долларовая
  оценка выводится пустой с причиной, не нулём (NFR-3).
- Монеты, выпущенные Bybit (BYUSDT, BBSOL), в коде не помечаются: признака в API
  нет. Их природа описывается агенту в `references/` на Э7.
- `totalPerpUPL` — только бессрочные и фьючерсы. Результат по опционам берётся из
  `option-asset-info`; их сумма — расчётное значение.
- Долларовая оценка монет кошелька финансирования: количество × `lastPrice`
  спотовой пары `МОНЕТАUSDT` — расчётная; USDT и USDC равны 1, помечены как точная
  оценка; нет пары — пусто с причиной. Итог кошелька — сырой из `asset-overview`.
- Portfolio Margin: биржа возвращает пустые `leverage`, `liqPrice`, `positionIM`,
  `positionMM`. Критерий приёмки 6 в этом режиме выполняется как пустое значение
  с причиной; маржа по опционам — `assetIM`/`assetMM` по базовой монете.
- Реализованный результат в `portfolio` — сырые `cumRealisedPnl` по монетам (в
  единицах монеты) и `totalRPL` по опционам; результат за период — `pnl` (Э4).

**Э3. Опционы.** `opt positions`, `opt greeks`, `opt chain`, `opt expiries`.
Ядро проекта, поэтому идёт раньше истории.

Учесть по живому прогону (2026-09-27):
- Символы опционов на счёте пользователя с суффиксом расчётной монеты:
  `BTC-27NOV26-104000-C-USDT`. В примерах документации формат без суффикса
  (`BTC-29JUL22-25000-C`). Разбор контракта обязан понимать оба; формат сверить с
  документацией до тестов.
- Базовые монеты опционов на счёте: BTC, ETH, SOL, MNT, XRP, XAUT (A-5: список не
  зашивается).
- `option-asset-info` уже даёт по базовой монете `totalDelta` (только позиции),
  `totalUPL`, `totalRPL`, `assetIM`, `assetMM`. `totalUPL` в USD: сверено с суммой
  позиций по BTC (213.68 против ≈211). Сравнить с `coin-greeks` для `opt greeks`.
- Греки в `position/list` по опционам — позиционные (масштабированы на размер):
  MNT, размер 1000, delta 164.2. Проверить по документации до расчёта нетто-греков.

Сверка перед Э3 (2026-09-27, документация и живой счёт):
- Греки позиции уже со знаком стороны (проданный пут: дельта +, гамма и вега −,
  тета +). В документации не описано.
- `coin-greeks`: гамма, вега, тета равны сумме по опционным позициям; `totalDelta`
  включает спот и бессрочные (BTC 0.2413 против −0.0087 по опционам). Решение
  пользователя: дельта по монете только опционная — `option-asset-info`.
- Формат символа (enum): `BTC-13FEB25-89000-P-USDT` — USDT, `ETH-28FEB25-2800-C` —
  USDC. Живьём: день без ведущего нуля (`9OCT26`), дробный страйк (`0.85`), USDC-
  опционов нет.
- `deliveryTime`: крипта 08:00 UTC, акции (NVDA, SPCX) 20:00 UTC — время
  экспирации по символу не определяется.
- `tickers` по опционам без курсора: BTC — 712 контрактов одним ответом.
- Portfolio Margin (живьём): MM монеты = худший убыток по сетке сценариев +
  `contingencyComponents`; IM = 1.2 × MM; MM счёта = сумма по монетам;
  `accountMMRate` = accountMM / equity, обрезано до 4 знаков. Маржи на отдельный
  опцион биржа не назначает.
- `portfolio-margin`: у опциона три числа `pnls` на сценарий цены, у итогов —
  одно. В примере документации (`maxLossIvShock` −0.2) итог равен сумме третьих,
  на счёте (+0.24) — первых: порядок IV вверх, без изменений, вниз. Выбор по знаку
  `maxLossIvShock`, сверка суммы с итогом OPTION; не сошлось — пусто с причиной.
- Кэш справочника (D-7) — на Э6; на Э3 справочник запрашивается каждый раз.

## 11. Риски

- **R-1. Права ключа.** Ключ только на чтение может не отдавать часть данных.
  Выясняется на Э1 через `query-api`, до того как написан остальной код.
- **R-2. Глубина два года.** Сделки, операции и закрытые позиции глубже не
  доступны. Это причина, по которой расчёт заработка построен на движении
  средств, а не на сумме сделок. Зафиксировано в спецификации как A-7.
- **R-3. Размер доски.** По популярной монете контрактов сотни. Нужна разумная
  фильтрация по умолчанию — ближайшая месячная экспирация (решение пользователя
  2026-09-27: недельные неполные), — иначе вывод неудобен и агенту, и человеку.
- **R-4. Экзотические монеты в истории вводов.** Для монеты без пары к USDT
  оценка невозможна. Решение принято в D-8: пустое значение с причиной.
- **R-5. Доступность биржи.** Bybit блокирует запросы с адресов США и
  материкового Китая. Диагностируется отдельным сообщением.
